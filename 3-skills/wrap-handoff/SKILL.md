# wrap-handoff

목적: 다음 담당자가 이어받을 수 있게 하고, 내가 내 결과물을 **내 말로** 설명할 수 있게 한다.

## A. 정리
1. **문서-코드 대조**: README, PROBLEM, DECISIONS, VERIFY, COMPONENTS, CHALLENGES에 적힌 주장(수치, 규칙, 기능, 지시 원문, 커밋 해시)을 실제 코드·테스트·로그와 대조한다. 불일치는 고치거나 문서를 정정한다.
2. 전체 테스트를 실행하고 결과를 보여 준다.
3. `HANDOFF.md`: 한 줄 요약 / 실행 방법(복붙 가능한 명령) / 구조와 파일 역할 / 결정론적 코드와 LLM 영역 / 성공 기준 달성표(근거 위치) / 주요 결정 / 남은 일 / 알려진 위험.
4. VERIFY.md "알려진 한계/위험"에 **운영 중 깨질 지점 5개**: `약점 → 어디까지 번지나 → 검증·개선 계획`.
5. CHALLENGES.md 맨 위 요약표에 상위 3건을 고른다.
6. `git log --oneline`으로 흐름(세팅 → 문제 정의 → 기능 → 수정 → 정리)에 빈 단계가 없는지 보고, GIT.md 형식으로 최종 커밋: `docs: 인수인계·검증 정리`

## B. 설명 스크립트 (화면에만 출력, 파일 저장 안 함)
각 3~5문장, 사용자 1인칭, 고유명사(파일·함수·수치·현업 발언) 포함. 기록에 없는 내용은 지어내지 말고 사용자에게 묻는다.
1. **전체 구성 (30초)**: "이 도구는 <누구>의 <문제>를 해결합니다. 흐름은 <단계1> → <단계2> → <단계3>입니다."
2. **구성별 책임**: "<구성>은 <책임>만 맡습니다. <입력> → <출력>. 따로 둔 이유는 <이유>, 깨지면 <영향>." + "구조는 제가 정했고 구현은 AI에게 맡겨 <테스트>로 확인했습니다."
3. **방법 선택 이유**: "<채택안>을 썼습니다. <특성> 때문에 <기준선>으로는 <약점>. 같은 데이터에서 <지표> <값> vs <값>. 한계는 <한계>, <대비책>으로 보완."
4. **챌린지 1·2**: "<상황>에서 <수치>를 보고 <문제>를 인식했습니다. AI에게 '<지시 요지>'라고 지시했고, AI가 <결과>를 냈는데 <틀린 점>을 <수정>했습니다. <검증>으로 <전 → 후>."
5. **AI 역할 분담**: "<정의·구조·기준값·검증 기준>은 제가, <구현·테스트 작성·집계>는 AI가. AI 제안 중 <X>는 <근거>로 거절했습니다."
6. **약점과 다음 계획**: "약점은 <위치>. <상황>에서 <영향>. <방법>으로 확인하고 <개선>하겠습니다."
7. **외울 키워드 10개**: 수치, 함수 이름, 기준값, 커밋 핵심어를 한 줄로.
