# problem-brief

목적: 들은 내용을 문서로 고정하고, **빈칸을 찾는다.** 실무자를 대신해 요구사항을 지어내지 않는다.

## 절차
1. 사용자가 붙여 넣은 인터뷰 내용을 읽는다.
2. PROBLEM.md의 각 칸을 채운다. 실무자가 **직접 말한 것만** 쓰고, 출처 표시(예: "(실무자 2번째 답)")를 붙인다.
3. 추측이 필요한 칸은 비워 두고 "가정(확인 필요)"에 넣는다.
4. 아래 체크리스트에서 비어 있는 항목을 질문으로 만든다:
   - [ ] 실제 에피소드(최근 사례)
   - [ ] 현재 우회 방법과 걸리는 시간
   - [ ] 성공 기준 **숫자** (건수, 시간, 정확도)
   - [ ] 쓰는 사람, 보는 시점, 결과를 받는 사람
   - [ ] 제외해야 할 상황과 예외(정비, 테스트, 재작업 등)
   - [ ] 제약: 보안(외부 반출, 외부 LLM 사용 여부), 실행 환경, 형식
   - [ ] 우선순위(Must/Should/Won't)
   - [ ] "제가 안 여쭤봤는데 꼭 알아야 할 것"
5. 실무자에게 보낼 **합의서 초안**(문제, 성공 기준, 범위, 제약, 가정)을 만든다.

## 출력
- 갱신된 PROBLEM.md (파일에 저장)
- 남은 질문 목록: 사소한 맥락 질문부터, 한 번에 1~2개씩 보낼 수 있게 순서대로
- 합의서 초안
