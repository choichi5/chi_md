# kickoff

목적: 코딩 전에 상황과 데이터 함정을 파악하고, 기록을 남길 틀을 세운다. **이 단계에서는 구현하지 않는다.**

## A. 저장소·문서 틀
1. 현재 상태 파악: `ls -la`, `git status`, `git log --oneline | head`, 루트 README와 과제 설명 전체.
2. git 저장소가 아니면 `git init`. `.gitignore`가 없으면 GIT.md의 기본 목록으로 만든다.
3. 없는 문서만 빈 틀로 만든다: `AGENTS.md`, `PROBLEM.md`, `DECISIONS.md`, `VERIFY.md`, `COMPONENTS.md`, `CHALLENGES.md`.

## B. 데이터 점검 (제공 데이터가 있으면)
**발견한 것은 고치지 말고 질문으로 만든다.** 처리 규칙은 현업 답을 들은 뒤에 정한다.
1. 행 수, 열, 자료형, 앞 5행
2. **시간 열**: 최소~최대. 과제 기간 밖 행은 **어떤 그룹(장비/사용자)에 몰려 있는지** 교차 집계
3. **범주 열**: 값별 개수, 대소문자·공백만 다른 같은 값
4. **수치 열**: 분포, 자릿수가 다른 그룹(단위 혼재 의심), -999/0/음수 같은 특수값
5. **ID 열**: 중복, 접미사 패턴(끝에 R, _2 등)
6. 결측 비율, 보조 파일(일정표·스펙)과 본 데이터의 연결 방식
- 수치에는 **분모를 함께** 쓴다(예: "INFO 1,072/1,750 = 61.3%"). 무엇을 기준으로 센 것인지 표 제목에 쓴다.
- 결과는 VERIFY.md 맨 위 "데이터 점검" 절에 남긴다.

## C. 커밋
GIT.md 절차로 커밋: `chore: 작업 지침·문서 틀 세팅`

## 보고 (짧게)
- 과제 한 줄 요약, 제공 파일과 용도
- 데이터 이상 신호 표: `발견 | 근거(수치/분모) | 현업에게 할 질문`
- 아직 정하지 않은 것: 성공 기준(숫자), 사용자, 실행 환경, 제약(보안·외부 반출)
