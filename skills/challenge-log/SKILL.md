# challenge-log

목적: "어떤 문제를 어떻게 인식했고, AI에게 무엇을 지시해서 어떻게 극복했나"를 **일이 일어난 그 자리에서** 남긴다. 기억으로 나중에 쓰면 틀리고, 로그와 어긋나면 감점이다.

## 실행 시점 (하나라도 해당하면 실행)
- 데이터·출력에서 예상과 다른 수치를 발견했다
- 테스트가 실패했거나 버그를 고쳤다
- AI(자신 포함)의 제안·코드를 사람이 거절하거나 고쳤다
- 현업 답변 때문에 설계·범위를 바꿨다
- 과한 설계를 줄였다 (scope-check 결과)

## 절차
1. `CHALLENGES.md`가 없으면 템플릿으로 만든다.
2. 다음 번호로 한 건을 추가한다. 칸은 템플릿 순서 그대로:
   상황 / 문제 인식(어떻게 알았나: 수치·출력·발언) / 원인 가설 / **AI에게 보낸 지시 원문** / AI 결과 / 사람의 판단·수정 / 검증(명령 → 수치) / 결과(전 → 후) / 증거 / 배운 것·남은 위험
3. **지시 원문**은 이번 세션에서 사용자가 실제로 보낸 메시지를 그대로 인용한다. 요약하거나 다듬지 않는다. 여러 번이면 순서대로 모두.
4. 사람이 한 판단과 AI가 한 일을 구분해서 쓴다. AI가 한 것을 사람이 한 것처럼 쓰지 않는다.
5. 아직 검증하지 않았으면 `검증: 미실행`으로 두고, 검증 후 갱신한다.
6. 수정 커밋이 있으면 해시를 증거에 넣는다(커밋은 `git-commit` 절차를 따른다).
