# scope-check

목적: AI가 만든 범용적이고 "완벽한" 설계를 요구사항 크기로 깎는다. 오버엔지니어링은 감점이다.

## 절차
1. PROBLEM.md의 성공 기준, 사용자, 실행 환경을 읽는다.
2. 코드의 주요 기능과 모듈을 나열하고, 각각을 성공 기준 번호에 연결한다.
3. 어디에도 연결되지 않거나, 연결되더라도 필요 이상인 것을 표시한다. 예:
   - 실무자가 요구하지 않은 보안·무결성 장치(해시, 서명, 바이트 단위 비교)
   - 한 번 쓰는 기능의 설정 시스템이나 플러그인 구조
   - 실행 환경에 비해 무거운 의존성(서버, DB, 빌드 도구)
   - 요구보다 넓은 입력 형식 지원
4. 표로 보고한다: `기능 | 연결된 성공 기준 | 판정(유지/축소/제거) | 이유`
5. **삭제는 사용자 승인 후에만** 한다. 승인되면 제거하고 DECISIONS.md에 "범위 축소: X — 이유"를 남긴다.

## 주의
- 성공 기준에 필요한 검증(행 수 대조 같은 것)은 유지한다. 줄이는 대상은 "필요 이상"인 부분이다.
- 반대로 성공 기준인데 아직 구현되지 않은 것이 있으면 함께 알린다.
