# wrap-handoff

목적: 다음 담당자가 이어받을 수 있게 하고, 내가 내 설계를 설명할 수 있게 한다.

## 절차
1. **문서-코드 대조**: README, PROBLEM, DECISIONS, VERIFY에 적힌 주장(수치, 규칙, 기능)을 하나씩 코드나 테스트로 확인한다. 불일치는 고치거나 문서를 정정한다.
2. 전체 테스트를 실행하고 결과를 보여 준다.
3. `HANDOFF.md` 작성: 한 줄 요약 / 실행 방법(복붙 가능한 명령) / 구조와 각 파일 역할 / 결정론적 코드 영역과 LLM 영역 / 성공 기준 달성표(근거 위치 포함) / 주요 결정 / 남은 일 / 알려진 위험.
4. VERIFY.md "알려진 한계/위험"에 **운영 중 깨질 가능성이 높은 지점 5개**를 적는다. 각 항목은 `약점 → 어디까지 번지는지 → 검증·개선 계획`의 3단으로 쓴다.
5. CHALLENGES.md 맨 위 요약표에 상위 3건을 고른다.
5-1. `explain-prep` 절차를 실행해 사용자가 AI 없이 설명할 답변 스크립트(구성·책임, 챌린지 2건, AI 역할 분담, 약점)를 화면에 보여 준다.
6. `git log --oneline`을 읽고 흐름(세팅 → 문제 정의 → 기능 → 수정 → 정리)에 빈 단계가 없는지 본다.
7. `git-commit` 스킬 절차로 최종 커밋: `docs: 인수인계·검증 정리`
